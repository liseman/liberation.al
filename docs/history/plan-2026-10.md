# Original wearable plan, October 2026

This is a historical design summary, not the current installation guide or a
record of deployed hardware. The original implementation notes and measurements were removed. See [Architecture](../ARCHITECTURE.md) for the running
system and [Roadmap](../ROADMAP.md) for current work.

## Intended experience

A wearable assistant would listen through a collar microphone, speak through bone
conduction, and observe the surroundings through overlapping cameras. Local
inference and evidence-backed recall were the central goals. A separate ambient
microphone array would record conversations and provide speaker direction.

## Hardware ideas

| Area | Original proposal | Unresolved work |
|---|---|---|
| Compute | Apple Silicon computer carried in a pack | Power, cooling, and mounting under sustained load |
| Voice input | Throat microphone through a wireless USB receiver | End-to-end acoustic validation |
| Ambient audio | USB microphone array with hardware echo cancellation and direction of arrival | Measure speech capture and direction on the assembled pack |
| Voice output | Bone-conduction output from the microphone array, with an external amplifier as an alternative | Output level, intelligibility, and feedback |
| Surrounding vision | Three overlapping USB fisheye cameras connected to the main computer | Lens calibration, USB bandwidth, and camera stability |
| Body sensing | Microcontroller with inertial, environmental, and haptic devices | Wiring and integration |
| Place memory | Satellite computer with stereo depth and inertial sensing | Mapping and synchronization |
| Projection | Projector with depth-assisted surface calibration and touch input | Hardware selection and calibration |

The earliest plan put panorama stitching on a second satellite. Later design work
favored sending the three camera views directly to the main computer. Neither
that choice nor an old benchmark establishes the performance of a future wearable
assembly.

## Validation goals

- Measure latency from captured speech to the first audible response, including
  the actual input and output devices.
- Run concurrent sensing and inference long enough to expose thermal throttling,
  model contention, and device failures.
- Distinguish a software replay from a live acoustic test, and a synthetic frame
  benchmark from a real camera stream.
- Keep person identification separate from a model's scene description.
- Measure projection alignment, touch latency, and mapping accuracy before
  presenting them as working capabilities.

The original model list, flat `software/` layout, manual install commands, and
per-machine deployment log were superseded. Current model declarations live in
[`config/defaults.toml`](../../config/defaults.toml), and setup is documented in
[`README.md`](../../README.md).
